# Original saved-directory, body-prefix and KSAV section inspection

This standalone host links three original pure managed source files. It has no game, Unity or Core dependency and does not install hooks, execute saved types/callbacks, invoke native readers or write a save. The .NET Standard 2.1 build checks the same product code's compilation contract.

The parser owns copied immutable bytes, reads bounded little-endian values, parses saved descriptor trees without resolving their type names, frames every top-level root/component before known-layout decoding, and descends through recognized Storage packet records. Marker, KPrefabID, Tag and inherited Storage fields are read in their saved order. Unknown component bytes and the body tail remain unchanged. Structural failure throws a typed exception and returns no report. Marker/identity conflicts are explicit semantic diagnostics; no winner is selected.

Every successful report still says `WholeFilePreflightProven=false`, `GeneralDescendantCoverageProven=false` and `OwnedRestorePermitted=false`. The section inspector accepts a caller-supplied KSAV start. The separate closed prefix inspector can derive that start strictly from immutable inflated-body byte zero; neither layer searches for magic/component strings. Arbitrary custom-detail payloads may contain further roots and remain outside recognized Storage traversal. The tool does not validate native Sim contents, reconcile a checkpoint owner manifest, assign a marker, quarantine a prefab or permit an owned load/save.

The prefix inspector accepts only the supported exact field sets and recursive descriptors for `Klei.SaveFileRoot`, `Game+Settings` and value-type `KMod.Label`, walking their saved order. Typed top-level values have no outer object-length envelope. Streamed dictionary values precede all keys; byte arrays are preserved as immutable ranges. All collection claims must equal independently walked consumption; they never control a skip. Canonical null `requiredMods` is exactly `(length=0,count=-1)` and needs no saved `ModInfo` template. Every non-null `requiredMods`, including empty, is Unsupported: native value-list mapping requires the missing element template even at count zero. Non-null `active_mods` requires the exact Label template even when empty, and each Label is four direct saved members with no reference-object wrapper. Changed value/reference flags, null streamed/active collections and the exact legacy streamed key `Sim` are rejected.

After the exact markers and members, the prefix layer consumes one bounded inline Int32 Sim length and its opaque bytes. Its end is the only candidate KSAV offset. It verifies the header there and returns immutable ranges and primitive observations; compose the unchanged section inspector at that offset for complete supported KSAV framing. Zero-length Sim and recorded grid dimensions establish no native validity. Prefix reports additionally keep `NativeGridValidityProven`, `NativeSimValidityProven`, `NativeLoadPermitted`, `WriterPermission` and `QuarantineActivated` false. Body/directory association with an outer save remains the caller's responsibility.

Synthetic fixtures are independently authored byte streams, not calls to native KSerialization or the parser's own writer (the parser has no writer). Checks cover saved-order inherited fields, nested positive native packets, descriptor trees, zero/null/assigned markers, exact Int64 values, raw float bits, opaque bytes containing misleading magic/type strings, duplicate later identities, malformed/truncated framing, strict UTF-8, all resource budgets and immutable copy/collection behavior. Ordinary positive native packets must remain present; they are never dropped or rewritten to fit custom ownership.

The additional independently authored prefix checks cover saved-order permutations, values-before-keys, nullable/empty arrays and strings, null-versus-empty requiredMods, direct Label values, exact Int64 bits, forged inner/outer lengths and count plausibility, every truncated synthetic prefix, decoy markers, unsupported type flags, malformed UTF-8, immutable outputs and every resource cap. Structural failure throws a typed exception and returns no partial candidate.

The default host now runs 43 synthetic groups; the optional derived v38 capture adds one. Both Windows and Linux pass all 44 and their separate .NET Standard 2.1 contract builds. A private fresh Windows-v39 ordinary colony additionally runs these same three product sources in actual ONI Mono 6.13 after native save/menu/reload returns. Its body-derived KSAV start 9472651 and section end 10445583 agree with separate native entry/return observations; captured image hashes, native packet identity and all permission denials are checked. This runtime check uses archived copied files, never the live native reader. The first cached-world launch failed before colony startup/parser execution and is preserved separately. See [the game evidence and remaining boundaries](../../docs/owned-reservoir-bridge.md#saved-template-and-object-section-inspection).

Default limits cap the image at 1 GiB, directory at 64 MiB, 65,536 templates/members/groups, 262,144 total recognized roots, 4,096 components per root/1,048,576 total, 64 Storage levels, 32 descriptor levels/262,144 nodes, 1,048,576 total Tag elements, 16 KiB type/component/group names, 4 KiB member names and 1 MiB value strings. Caller limits may be stricter and are constructor validated. Counts must also fit enclosing byte ranges before allocating records. These are bounded compatibility limits, not a guarantee for every possible ONI/mod save.

The prefix layer separately caps metadata through the inline Sim length at 64 MiB, streamed entries/Labels at 4,096 each, one/aggregate streamed value payloads at 64 MiB, one decoded UTF-8 payload at 1 MiB and their aggregate at 16 MiB, and the opaque inline Sim blob at 512 MiB. Count minima (12 bytes per dictionary entry and 20 per Label), physical remaining bytes and the enclosing claim are checked before record allocation. String and raw-blob limits are checked before decoding or taking their ranges. Caller limits can only tighten these hard caps.
